# 디자인 검수 체크리스트

검수자는 각 항목의 `[ ]`를 `[x]` 또는 `[!]`로 바꾸고 의견을 남깁니다. 화면 파일은 `screen-inventory.md`와 동일합니다.

## 구조·내비게이션

- [ ] 좌측 사이드바가 모든 데스크톱 화면에서 동일한 위치/순서로 유지된다.
- [ ] 모바일에서 `원본 / 편집 / 검토` 외에 중복 workflow 내비게이션이 생기지 않는다.
- [ ] 페이지 제목과 요약이 현재 객체/큐의 이름을 말한다.
- [ ] `본문으로 건너뛰기`와 주요 heading 흐름이 자연스럽다.

## 원본·신뢰 의미

- [ ] 원본 상세에 스냅샷 버전, readiness, 권리 상태, 원문이 함께 보인다.
- [ ] 모델 자동 평가와 사람 원본 대조가 서로 다른 텍스트/상태로 보인다.
- [ ] Review의 11건 미확인 사실 블록이 실제 승인 차단 이유와 일치한다.
- [ ] source update/stale/partial 범위는 색상만이 아니라 설명과 다음 행동으로 전달된다.

## Planner·채널

- [ ] Creator Identity 사실 입력에 evidence URL/설명이 보인다.
- [ ] 원본 기반 기본값이 Planner 공통 맥락에 실제로 채워진다.
- [ ] 채널별 목적·구조·Preview·검사 기준이 구분된다.
- [ ] 체크하지 않은 채널을 생성한다고 오해할 수 있는 버튼/문구가 없다.

## 상호작용

- [ ] RSS/전사/YouTube 대화상자의 닫기·필수 필드·도움말이 작동한다.
- [ ] Review의 미리보기/검사/버전/실행 탭이 실제 패널을 교체한다.
- [ ] 사람 대조 큐에서 다음 항목과 개별 항목 선택이 실제 블록/원본 위치를 바꾼다.
- [ ] 승인 차단 상태에서 승인 버튼이 비활성이고 인접한 이유가 읽힌다.
- [ ] 실패/재시도/내보내기 컨트롤이 실제 다음 행동을 제공한다.

## 반응형·접근성

- [ ] 모바일 터치 대상이 충분히 크고, sticky 승인 영역이 콘텐츠를 가리지 않는다.
- [ ] 탭의 선택 상태와 panel 연결이 시각·ARIA 모두에서 일치한다.
- [ ] 키보드만으로 검색, 필터, 대화상자, Review 블록을 이동할 수 있다.
- [ ] 의미 있는 본문/메타데이터가 읽기 가능한 글자 크기와 줄 간격을 유지한다.
- [ ] 색상 없이도 배지 텍스트/아이콘만으로 상태를 구별할 수 있다.

## 외부 경계

- [ ] 승인 후 Markdown export가 현재 버전 기준으로 다운로드된다.
- [ ] WordPress는 publish가 아니라 draft 경계로 남는다.
- [ ] 실제 WordPress App Password draft canary를 별도 환경에서 확인한다.
- [ ] 실제 Naver/YouTube/Short 플랫폼 렌더링은 해당 계정에서 별도로 확인한다.
